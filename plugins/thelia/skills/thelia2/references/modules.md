# Thelia 2.6: Modules: complete setup

> Source: `core/lib/Thelia/Module/BaseModule.php`, `Thelia.php:470-509`, `ModuleManagement.php`, `SchemaLocator.php:173`. Convention: `local/modules/{Name}/`.

## 1. Canonical directory structure

```
local/modules/MyModule/
+- MyModule.php                       # extends BaseModule (FQCN = <fullnamespace> from module.xml)
+- composer.json                      # OPTIONAL if distributed via Composer
+- Config/
|  +- module.xml                      # REQUIRED (XSD module-2_2.xsd)
|  +- config.xml                      # REQUIRED EVEN IF EMPTY (XSD thelia-1.0.xsd)
|  +- schema.xml                      # OPTIONAL (Propel schema)
|  +- thelia.sql                      # Initial SQL (postActivation)
|  +- routing.xml                     # OPTIONAL (prefer #[Route] PHP 8; see code-patterns.md sec.7)
|  +- update/                         # Versioned *.sql files, semver (watch case)
+- Command/                           # #[AsCommand] SF 6.4
+- Hook/                              # extends BaseHook
+- Loop/                              # extends BaseLoop + PropelSearchLoopInterface
+- Form/                              # extends BaseForm
+- Controller/Front, Controller/Admin # extends BaseFront/AdminController
+- EventListener/                     # #[AsEventListener] SF 6.x
+- Api/Resource/                      # PropelResourceInterface
+- Model/                             # Generated by Propel from schema.xml
+- I18n/                              # en_US.php, fr_FR.php
+- templates/
   +- frontOffice/default/...html
   +- backOffice/default/...html
```

The Thelia root `composer.json` declares `"": ["local/modules/"]` in PSR-4; a local module does not need its own `composer.json` autoload to function. The `composer.json` is only required for Composer distribution.

## 2. BaseModule: 8 lifecycle methods

`BaseModule.php:502-534` declares the 8 methods called by `BaseModule::activate()` (`L111`) and `deactivate()`.

| # | Method | Signature | Contract | Pitfall |
|---|---|---|---|---|
| 1 | `install` | `install(ConnectionInterface $con = null): void` | First discovery. Wrapped by `ModuleManagement::updateModule()` (`L119`) | No second transaction |
| 2 | `update` | `update($currentVersion, $newVersion, ConnectionInterface $con = null): void` | If `module.xml.version > DB version` | No-op by default. The module MUST load its .sql files |
| 3 | `preActivation` | `preActivation(ConnectionInterface $con = null): bool` | Return `true` required. `false` silently rolls back | An exception also rolls back |
| 4 | `postActivation` | `postActivation(ConnectionInterface $con = null): void` | Inside the activation transaction | Idempotency is essential (`is_initialized`) |
| 5 | `registerHooks` | `registerHooks(): void` | **OUTSIDE transaction**, after `$con->commit()` | **MAJOR PITFALL**: exception here = module active without hooks |
| 6 | `preDeactivation` | `preDeactivation(ConnectionInterface $con = null): bool` | Return `bool` | Same as preActivation |
| 7 | `postDeactivation` | `postDeactivation(ConnectionInterface $con = null): void` | Inside the transaction | (none) |
| 8 | `destroy` | `destroy(ConnectionInterface $con = null, $deleteModuleData = false): void` | Manual removal (admin) | `$deleteModuleData=true` must purge tables |

## 3. module.xml

XSD: `core/lib/Thelia/Module/schema/module/module-2_2.xsd`.

Required fields:
- `<fullnamespace>`: FQCN of the Module class
- `<descriptive locale="..."><title>...</title></descriptive>`: at least one
- `<languages><language>...</language></languages>`
- `<version>`: semver compared to DB version
- `<type>`: `classic` / `delivery` / `payment` / `marketplace` / `price` / `accounting` / `seo` / `administration` / `statistic`
- `<stability>`: `alpha` / `beta` / `rc` / `prod` / `other`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<module xmlns="http://thelia.net/schema/dic/module"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="http://thelia.net/schema/dic/module http://thelia.net/schema/dic/module/module-2_2.xsd">
    <fullnamespace>MyModule\MyModule</fullnamespace>
    <descriptive locale="en_US"><title>My Module</title></descriptive>
    <languages><language>en_US</language></languages>
    <version>1.0.0</version>
    <authors><author><name>Dev</name><email>dev@example.com</email></author></authors>
    <type>classic</type>
    <thelia>2.6.0</thelia>
    <stability>prod</stability>
    <mandatory>0</mandatory>
    <hidden>0</hidden>
</module>
```

## 4. config.xml: minimal with autoconfigure

XSD: `core/lib/Thelia/Core/DependencyInjection/Loader/schema/dic/config/thelia-1.0.xsd`. **Required EVEN IF EMPTY** (`Thelia.php:555` loads without try/catch in dev; in production the exception is swallowed and silently logged, SIGNAL-03).

### What is auto-tagged by autoconfigure

`Thelia.php:470-509` registers via `registerForAutoconfiguration`:

| Interface | Auto tag | config.xml required? |
|---|---|---|
| `LoopInterface` | `thelia.loop` | No (snake_case auto via `RegisterLoopPass`) |
| `FormInterface` (Thelia) | `thelia.form` | No (`getName()` static auto FQCN) |
| `BaseHookInterface` | `hook.event_listener` | **YES**: tag placed without `event/type/method` -> `RegisterHookListenersPass:120` iterates on empty events silently (SIGNAL-06). Always declare `<hook>` XML. |
| `FilterInterface` (Propel) | `thelia.api.propel.filter` | No |
| `ResourceAddonInterface` | `thelia.api.resource.addon` | No |
| `QueryCollectionExtensionInterface` | `thelia.api.propel.query_extension.collection` | No |
| `QueryItemExtensionInterface` | `thelia.api.propel.query_extension.item` | No |
| `SerializerInterface` | `thelia.serializer` | No |
| `ArchiverInterface` | `thelia.archiver` | No |
| `ControllerInterface` | `controller.service_arguments` | No |
| `ContainerAwareInterface` (commands) | `thelia.command` | No |

## 5. schema.xml: Propel

XSD: Propel 1.6. The root namespace `<database name="TheliaMain">` is required to point to the main connection (`SchemaLocator.php:173`). To declare a FK to a core table (Product, Customer...), add:

```xml
<external-schema filename="local/config/schema.xml" referenceOnly="true"/>
```

`referenceOnly="true"` prevents Propel from regenerating core models in the module.

### Propel behaviors observed in core

| Behavior | Usage | Parameters |
|---|---|---|
| `timestampable` | Auto `created_at`, `updated_at` | none |
| `i18n` | Generates `{table}_i18n` + `setLocale()/getLocale()` | `i18n_columns`: list of columns to translate |
| `versionable` | Version history (Product/Category) | `log_created_at`, `log_created_by` |

Note: `versionable=true` requires the consuming module to use `PropelSearchLoopInterface` (incompatible with `ArraySearchLoopInterface`).

### Minimal schema example

```xml
<?xml version="1.0" encoding="UTF-8"?>
<database xmlns="http://xsd.propelorm.org/1.6/database.xsd"
          name="TheliaMain" defaultIdMethod="native">
    <external-schema filename="local/config/schema.xml" referenceOnly="true"/>
    <table name="my_module_item" namespace="MyModule\Model">
        <column name="id" type="INTEGER" primaryKey="true" autoIncrement="true" required="true"/>
        <column name="visible" type="TINYINT" required="true" defaultValue="0"/>
        <column name="position" type="INTEGER" defaultValue="0"/>
        <column name="product_id" type="INTEGER"/>
        <foreign-key foreignTable="product" onDelete="CASCADE" onUpdate="RESTRICT">
            <reference local="product_id" foreign="id"/>
        </foreign-key>
        <behavior name="timestampable"/>
        <behavior name="i18n">
            <parameter name="i18n_columns" value="title, description"/>
        </behavior>
    </table>
</database>
```

## 7. SQL migrations: convention `Config/update/{version}.sql`

- Real convention: `Config/update/1.2.0.sql` (semver, compared with `version_compare()`).
- **Inconsistent casing across modules**: some distributed modules use `Config/Update/` (uppercase). Linux is case-sensitive; a module declaring `__DIR__.'/Config/Update/'` deployed on Linux as `Config/update/` loses its migrations in production (SIGNAL-04). **Always standardize on `update/` (lowercase).**
- No automatic core helper: each module implements its own loader.

### update() loader pattern

```php
public function update($currentVersion, $newVersion, ConnectionInterface $con = null): void
{
    $finder = (new \Symfony\Component\Finder\Finder())
        ->name('*.sql')->in(__DIR__.'/Config/update/')
        ->sort(fn(\SplFileInfo $a, \SplFileInfo $b) => version_compare(
            $a->getBasename('.sql'), $b->getBasename('.sql')
        ));
    $database = new \Thelia\Install\Database($con);
    foreach ($finder as $file) {
        if (version_compare($file->getBasename('.sql'), $currentVersion, '>')) {
            $database->insertSql(null, [$file->getPathname()]);
        }
    }
}
```

### Idempotent postActivation

```php
public function postActivation(ConnectionInterface $con = null): void
{
    if (!self::getConfigValue('is_initialized')) {
        (new \Thelia\Install\Database($con))->insertSql(null, [__DIR__.'/Config/thelia.sql']);
        self::setConfigValue('is_initialized', '1');
    }
}
```

The `is_initialized` guard is CRITICAL: `postActivation()` can be replayed (reactivation, partial reinstall) and an unguarded `INSERT` duplicates data.

## 8. Composer distribution

```json
{
    "name": "vendor/mymodule",
    "type": "thelia-module",
    "require": {"thelia/installer": "~1.1"},
    "extra": {"installer-name": "MyModule"}
}
```

`thelia/installer` deploys the module to `local/modules/{installer-name}/`. The module root `composer.json` does not need to declare PSR-4 autoload; Thelia handles that.

## 9. Module pitfalls (recap)

1. `config.xml` required EVEN IF EMPTY; silent crash in production without it (`Thelia.php:555` + `:572-577`)
2. SQL directory casing `Config/update/` vs `Config/Update/` (SIGNAL-04)
3. `registerHooks()` outside transaction; an exception here leaves the module active without hooks (`BaseModule.php:111`)
4. Incomplete auto-tag `BaseHookInterface`; always declare `<hook>` XML (SIGNAL-06)
5. `BaseModule::getModuleCode()` collides on last FQCN segment (`BaseModule.php:364`, SIGNAL-07): folder = short class name = module DB name; two distributed modules with the same short name conflict
6. `ModuleManagement::updateModules()` without ORDER BY: non-deterministic install order (SIGNAL-05)
7. `BaseHook` singleton instantiated pre-install crashes (`BaseHook.php:87-103`); do not register hooks in `preActivation`
8. **`DatabaseConfiguration` FQCN**: the real class is `Thelia\Config\DatabaseConfiguration` (`core/lib/Thelia/Config/DatabaseConfiguration.php`). `Thelia\Core\Propel\DatabaseConfiguration` **does not exist** and causes a `Class not found` fatal crash at runtime in any method using it.
